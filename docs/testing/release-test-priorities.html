QA plan · branch feature/shift-cash-phase1

What to test, in what order

The branch is one large unmerged release — a single-store back office becoming multi-business and multi-store, plus a new shift & cash workflow. This is the tester's triage sheet: every feature it adds, how finished it looks in the code, how hard it should be hit, and the checks that matter. Case IDs map to the interactive checklist at docs/testing/manual-test-plan.html.

Before you start. Run against a freshly seeded database with migrations 008–022 applied in order. There are no unit or component tests in this repo and only three back-end concurrency e2e tests — manual testing is the safety net for this release, so treat the P0 band as release-blocking.

How completeness is judged. Ratings come from reading the code (controllers, routes, entities, migrations), not a full functional pass — that's your job. "Built" means the endpoints and screens exist and are wired; "known gaps" are things the code already shows are missing or unguarded.

P0 — Foundation, test first

These decide who sees which business, which store is in scope, and whether the till reconciles. A defect here mis-scopes data or mis-counts cash for every module built on top, so none of the P1 work is trustworthy until this band is green.

Release context

  • Unmerged branch. feature/shift-cash-phase1 is ~471 files ahead of main. Test it as a single release, not incremental changes.
  • Seed & migrate first. Start from a clean seeded database and apply sql/migrations/008 through 022 in order; several depend on earlier ones. Rollback scripts ship alongside each.
  • No automated safety net. The repo has zero unit / component tests and only three back-end concurrency e2e tests — every case in the P0 band should be treated as release-blocking.
  • Companion checklist. docs/testing/manual-test-plan.html is the interactive run sheet — open it in a browser to record pass/fail, log issues, and export a Markdown findings report. The AUTH / CASH / PO / BIZ … IDs above are its case IDs.
